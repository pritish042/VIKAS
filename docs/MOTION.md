# VIKAS presentation motion — 9 October 2026

Existing dependencies contain no motion library. The implementation extends the current CSS animations and shared theme tokens, with no new dependency, API, provider call, database write or global scroll handler.

- Landing: 380–400ms text/section entrances, short stagger, and one 420ms aquamist background settling movement. Content is normally visible; animation failure or disabled JavaScript does not hide it. No intersection observer or scroll hijacking.
- Navigation: 180ms opacity/scale active surfaces and hover feedback. The redesign replaces the mobile workspace drawer with four direct bottom-navigation items. Account and guide overlays enter quickly and keep keyboard behaviour.
- Dashboard: 350ms card entrances on the initial ready dashboard view per verified account, not subsequent refreshes/visits. Progress keeps an accessible native progress element and animates only the visual fill's transform between actual task ratios (320ms); no loading percentage or activity is fabricated.
- Onboarding: 200ms question-body entrances using the existing step key. Answer state and the existing heading focus effect are unchanged; no transition waits or replacement focus logic.
- DISHA: only the reply ID returned by a new successful POST gets an entrance flag, cleared at animation end/on leaving. Loaded history is never marked for animation. Reduced motion does not mark new replies. Real pending requests show fixed-size opacity dots with readable status text. No typewriter animation or lesson content mutation.
- APRAJITA: small theme-based flower hover shadow, minimum-width Run control with actual loading state, and reserved output height. The CodeMirror editor receives no animation, remount, or sizing change.
- Dialogs: 200ms fade/scale. `MotionPresence` retains an inert, aria-hidden visual shell only on close; focus restoration, closing state, navigation and API execution are not delayed. Reduced motion skips retention. The shell is removed after 200ms even if animation events fail; timer cleanup handles reopen/unmount. Fresh modal opening keys preserve the previous reset behaviour, and account changes unmount any shell immediately.

Motion is mostly transform/opacity, with brief colour/border transitions and a small painted flower shadow only on hover. No permanent `will-change`, animation library, particles or background animation loop was added. Typing/Run opacity feedback runs only while a real request is pending. All effects follow the existing global `prefers-reduced-motion` override; CSS keyframes remain presentation-only.
